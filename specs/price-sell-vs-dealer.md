# 스펙: 부품 카테고리 판매가·딜러가 동시 수집 및 표시

> 작성일: 2026-09-15 · 작성: 클로드 코드 (사용자 "진행해"로 승인)
> 표기: [검증] 확인된 사실 · [추정] 추측 (구현 전 확인 필요)

## 1. 목표 (왜 만드는가)
- 그래픽카드/메인보드/CPU/Microsoft 크롤링 시 딜러가뿐 아니라 소비자 판매가·할인가도 함께 저장하고, 대시보드에서 딜러가/판매가를 전환해 볼 수 있게 한다.

## 2. 비목표 (이번엔 안 하는 것)
- 프리미엄PC/추천조립PC/아이웍스(recom 타입) 화면은 건드리지 않는다.
- Summary 탭, 가격 변동 모달(PriceHistoryModal)은 기존대로 딜러가 기준 유지.
- 과거 데이터 소급 재수집은 하지 않는다 (다음 크롤링부터 신규 필드가 쌓임).

## 3. 사용자 시나리오 (누가 → 무엇을)
- 담당자가 메인보드 탭에서 → 상단 토글로 "딜러가 / 판매가"를 전환해 30일 추이를 본다.
- 담당자가 엑셀 다운로드 → 딜러가 시트와 판매가 시트가 각각 들어 있는 파일을 받는다.

## 4. 화면 / 동작
| 화면·요소 | 동작 | 비고 |
|---|---|---|
| ProductListDashboard 필터 바 | SegmentedControl "딜러가 / 판매가" | 기본값 딜러가 |
| 가격 표 · 변동 표시 · 그래프 모달 | 선택된 가격 기준으로 표시 | 판매가 없는 날짜는 "-" |
| 엑셀 다운로드 | 시트 2개(딜러가, 판매가) | 기존 파일명 유지 |

## 5. 데이터 모델
- Firestore `compuzone_prices/{날짜}/{브랜드}/{ProductNo}` 문서에 필드 추가:
  - `sellPrice` 판매가 = 목록의 `data-price` [검증]
  - `promoPrice` 소비자 할인가 = `data-discountprice` [검증, 비로그인 페이지 기준]
  - `dealerPrice` 딜러가(맞춤가) = `data-customprice` [추정: 로그인 시 값이 채워짐]
  - `couponPrice` 쿠폰적용가 = `.price_Layer .sum dd`
- 기존 `originalPrice`, `discountPrice`는 호환을 위해 그대로 유지.
- 대시보드 판매가 조회 시 `sellPrice`가 없으면 `originalPrice`로 대체 (과거 데이터 호환).
- 마이그레이션 필요 여부: 없음 (Firestore 스키마리스).

## 6. 완료 기준 (= 검증 체크리스트) ⭐
- [x] 크롤러 추출 함수가 sellPrice/promoPrice/dealerPrice/couponPrice를 반환 (2026-09-15 메인보드 목록 5건 샘플 확인: 판매가 209,000 / 할인가 189,000 등)
- [x] 대시보드 타입체크(tsc --noEmit) 통과
- [x] 토글 전환 시 표 값이 바뀜 (로컬 dev 서버에서 메인보드 40행 중 33행 변경 확인, 예: 38,800 → 39,800)
- [x] 엑셀 파일에 시트 2개 생성 (node로 export 로직 시뮬레이션 확인)

## 7. 위험 요소 / 주의점
- 로그인 상태에서 `data-price`가 소비자 판매가로 유지됨 [검증]: 기존 저장 데이터의 originalPrice(39,800) > discountPrice(38,800)로 확인.
- Firestore 읽기 할당량: 필드 추가만이라 읽기 횟수 변화 없음.

## 8. 범위 밖 결정 사항 (나중을 위해 기록)
- Summary 탭에 판매가 열 추가 여부는 추후 결정.
